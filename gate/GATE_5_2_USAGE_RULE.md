# Gate 5.2 — Standing Usage Rule

**Status:** Active as of 2026-05-01 (Gate 5.2-R1 hardening pass applied)
**Authority:** Independent gate auditor, P04 of Gate 5.2 acceptance audit
**Supersedes:** `GATE_5_1_USAGE_RULE.md` (preserved at `/Users/syedhaider/Downloads/gate/GATE_5_1_USAGE_RULE.md` for reference)

Gate 5.2 preserves all Gate 5.1 behavior and adds executable enforcement for previously prose-only rules. Anything `tools/check_gate_package.py` accepted as PASS under 5.1 still PASSes under 5.2 (verified against the Lane D production package).

## Gate 5.2-R1 hardening summary

The R1 pass adds five blocking enforcements that were missing or advisory in 5.2.0:

1. **Host-path leakage** — every `raw_test_output` artifact must resolve INSIDE the
   exported package. Absolute host paths (e.g. `/tmp/...`) without a sibling
   `package_relative_path` fire `HOST_PATH_NOT_PACKAGE_EVIDENCE`.
2. **Profile metadata for ALL profiles** — `risk_tier`, `task_kind`, and a rationale are
   now mandatory in every `GATE_PROFILE_SELECTION.md`, including `GATE_LITE`.
3. **NOT_APPLICABLE proof is hard-blocking** — a missing `<STATE>_NOT_APPLICABLE.md` fires
   `MISSING_NOT_APPLICABLE_PROOF`; an empty/template-only file fires
   `NOT_APPLICABLE_REASON_MISSING`.
4. **Approved dirty-worktree labels** — `ACTIVE_PARALLEL_WORK_DO_NOT_TOUCH`,
   `AMBIENT_UNRELATED_DOC_COMMIT`, `UNRELATED_EXTERNAL_WORK`, and
   `UNRELATED_EXTERNAL_CHANGE_NEEDS_HUMAN` are accepted; `UNKNOWN_REQUIRES_HUMAN` blocks.
5. **Output-contract structured verdict** — `OUTPUT_CONTRACT_CONSISTENCY_AUDIT.md` should
   contain a fenced YAML block under key `output_contract_consistency:` with `verdict:`
   and `blocking_findings:`. Without one, the checker falls back to a negation-aware
   prose scan.

## Default lane assignment by task class

| Task class | Default profile |
|---|---|
| D0/D1 — docs, tiny patches, single-line fixes, comment edits | GATE_LITE |
| D2 — normal feature work, isolated bug fixes | GATE_STANDARD |
| D2-hot / D2_HOT — touches hot paths, retries, concurrency, request handling | GATE_FULL |
| D3 — multi-module changes, new subsystem, non-trivial refactor | GATE_FULL |
| D4 — runtime substrate changes, infra, gate changes themselves | GATE_FULL_PLUS_DOMAIN_ADDENDUM |

## Mandatory GATE_FULL_PLUS_DOMAIN_ADDENDUM cases (regardless of size)

- Database migrations (`task_kind: migration`)
- Production wiring — writing live state, calling production APIs (`task_kind: production_wiring`)
- Runtime/state machine changes (`task_kind: runtime_state`)
- Merge verification (`task_kind: merge_verification`)
- Release verification (`task_kind: release_verification`)
- Gate folder changes themselves (`task_kind: gate_change`)
- Prompt-authoring tools that affect downstream agents (`task_kind: prompt_authoring`)
- Model/provider routing changes (`task_kind: provider_model_routing`)
- Evidence-package work (`task_kind: evidence_package`)
- Any task that has already been corrected once and is back for revision

The Gate 5.2 checker mechanically enforces these via `required_min_profile()` — selecting `GATE_LITE` for any of the above fires `WRONG_GATE_PROFILE` and blocks PASS. This is no longer a prose-only rule.

## Profile-selection process

If a prompt does not specify a lane, run profile selection using an independent reviewer/subagent before starting. **Do not let the implementer self-select.**

The implementer-self-select pattern is the same anti-pattern that allowed prior packages to claim PASS by choosing GATE_LITE for tasks that warranted GATE_FULL.

The independent profile-selection step uses `GATE_PROFILE_SELECTOR.md` and writes `GATE_PROFILE_SELECTION.md` (with explicit `risk_tier`, `task_kind`, `selected_profile`, and a non-empty `reason`/`profile_selection_rationale`) before any implementation work begins.

Gate 5.2 also fires `MISSING_RISK_TIER`, `MISSING_TASK_KIND`, `MISSING_PROFILE_REASON`, `UNKNOWN_GATE_PROFILE`, `UNKNOWN_RISK_TIER`, `UNKNOWN_TASK_KIND`, and `PROFILE_SELECTION_DISAGREEMENT` (CLI vs file mismatch) flags.

## Mandatory final-signout contents (verified by checker)

- All required proof files for the selected profile, **at the exact relative path** `reports/<task_area>/<filename>` (Gate 5.2 enforces exact paths — basename matches in the wrong folder no longer count; flag `REQUIRED_PROOF_FILE_WRONG_PATH_OR_MISSING`)
- `gate_used/` directory or `gate_hash.txt`
- `GATE_PACKAGE_VALIDATION_REPORT.md` generated by `tools/check_gate_package.py --final` (`MISSING_CHECKER_REPORT_FINAL_MODE` blocks otherwise)
- For `GATE_FULL` and stronger: `OUTPUT_CONTRACT_CONSISTENCY_AUDIT.md` (or explicit `_NOT_APPLICABLE.md` with a recorded reason)
- Raw test outputs ending with `EXIT_CODE:0` (exact match: `^EXIT_CODE:0\s*$`; blank, missing, conflicting, or non-numeric values block)
- For `GATE_STANDARD` and stronger: summary docs claiming `EXIT_CODE:0` must be backed by a raw output that proves it (`EXIT_CODE_ONLY_IN_SUMMARY_NOT_RAW` blocks)
- No post-PASS uncaught errors in any raw output (`POST_PASS_UNCAUGHT_ERROR` blocks)
- A `git_status_final.txt` file: empty, marked clean, or with every dirty path classified using one of the **approved dirty-worktree labels** (Gate 5.2-R1):
  - `ACTIVE_PARALLEL_WORK_DO_NOT_TOUCH`
  - `AMBIENT_UNRELATED_DOC_COMMIT`
  - `UNRELATED_EXTERNAL_WORK`
  - `UNRELATED_EXTERNAL_CHANGE_NEEDS_HUMAN`

  Classification lives in `DIRTY_WORKTREE_CLASSIFICATION.md` / `DIRTY_WORKTREE_RECURRENCE.md` / `DIRTY_WORKTREE_RECURRENCE_AUDIT.md`. Always-blocking regardless of label: `node_modules`, `.run_artifacts`, `raw_test_output`, `raw_outputs`, generated `DOC_FRESHNESS_REPORT.md` in repo. Unclassified dirty paths fire `DIRTY_PATH_NOT_CLASSIFIED`; classification `UNKNOWN_REQUIRES_HUMAN` fires `UNKNOWN_REQUIRES_HUMAN_BLOCKER`.
- For `GATE_FULL`: `package_file_sizes.txt` and `package_file_hashes.txt`

If `tools/check_gate_package.py --final` exits nonzero, **do not return PASS** — fix the underlying issue and rerun.

## How to run the checker

```bash
python3 "/Users/syedhaider/Downloads/gate/tools/check_gate_package.py" \
  --package <your-export-package-folder-or-zip> \
  --profile GATE_FULL \
  --task-area <task_area> \
  --risk-tier <risk> \
  --task-kind <kind> \
  --gate-dir "/Users/syedhaider/Downloads/gate" \
  --final
```

(If `/Users/syedhaider/Downloads/gate 5.2` is the canonical install on your system, substitute that path — quoted because of the space.)

Exit codes:
- `0` — all required checks pass
- `1` — one or more checks failed (fix and rerun)
- `2` — configuration error (missing package, missing YAML, bad zip, missing gate-dir)

`--final` is required for the very last validation run (the one whose report is included in the signout package). Earlier exploratory runs may omit `--final`; in non-final mode the missing-validation-report state is treated as a SKIP-with-PASS to avoid circular dependency on the first run.

## Standing limitations to be aware of (Gate 5.3 backlog)

1. **Display-only path-trim bug** in `dirty_paths_from_git_status` (chops one extra char from dirty paths in failure messages). Cosmetic only — classification still correct.
2. **No fixtures for `EXIT_CODE_CONFLICTING` or `EXIT_CODE_NON_NUMERIC`.** Code paths exist but are unexercised by the self-test suite.
3. **`SUMMARY_DOC_PATTERNS` glob is broad** (`*SUMMARY*.md`) — a doc that legitimately quotes `EXIT_CODE:0` in a code example could trigger `EXIT_CODE_ONLY_IN_SUMMARY_NOT_RAW` falsely. Operator vigilance suggested for unusual doc names.
4. **Domain-addendum file existence is not enforced** for `GATE_FULL_PLUS_DOMAIN_ADDENDUM` — the YAML template `DOMAIN_ADDENDUM_{name}.md` is silently skipped. Acknowledged in `reports/gate-5-2/GATE_5_2_KNOWN_LIMITATIONS.md`.
5. **`not_applicable_proof_required` is a soft warning, not a hard fail.** Operators should still produce the explicit `_NOT_APPLICABLE.md` files; the checker only emits PASS-with-WARN if missing.

## Operator checklist before declaring PASS

```
[ ] Profile selected by independent reviewer/subagent (not implementer)
[ ] GATE_PROFILE_SELECTION.md has selected_profile, risk_tier, task_kind, and a non-empty reason
    (Gate 5.2-R1: required for every profile, including GATE_LITE)
[ ] All required proof files for the selected profile present at exact relative paths
[ ] All NOT_APPLICABLE proof files for the selected profile present with substantive reason
    (Gate 5.2-R1: missing-or-template NA proofs are blocking)
[ ] No raw_test_output declared via absolute host path without an in-package copy
    (Gate 5.2-R1: HOST_PATH_NOT_PACKAGE_EVIDENCE blocks)
[ ] gate_used/ or gate_hash.txt present
[ ] OUTPUT_CONTRACT_CONSISTENCY_AUDIT.md present (or _NOT_APPLICABLE with reason) for FULL profiles
    Prefer the Gate 5.2-R1 structured verdict block — see template
[ ] Every raw test output ends with EXIT_CODE:0 (exact)
[ ] No summary doc claims EXIT_CODE:0 unsupported by a raw output (FULL/STANDARD)
[ ] No post-PASS errors in any raw output
[ ] git_status_final.txt: clean, empty, or every dirty path classified with one of the
    Gate 5.2-R1 approved labels: ACTIVE_PARALLEL_WORK_DO_NOT_TOUCH /
    AMBIENT_UNRELATED_DOC_COMMIT / UNRELATED_EXTERNAL_WORK / UNRELATED_EXTERNAL_CHANGE_NEEDS_HUMAN
[ ] tools/check_gate_package.py --final exits 0
[ ] GATE_PACKAGE_VALIDATION_REPORT.md included in package after final rerun
[ ] Any task in the mandatory FULL_PLUS list uses GATE_FULL_PLUS_DOMAIN_ADDENDUM
[ ] If GATE_FULL_PLUS_DOMAIN_ADDENDUM, every named domain addendum file exists at its exact path
```

If any item is unchecked, do not declare PASS.

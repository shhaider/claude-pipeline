# Gate 5.1 — Standing Usage Rule

**Status:** Active as of 2026-05-01
**Authority:** Independent gate auditor, P04 of acceptance audit
**Supersedes:** Any informal lane-selection convention previously in use

---

## Default lane assignment by task class

| Task class | Default profile |
|---|---|
| D0/D1 — docs, tiny patches, single-line fixes, comment edits | GATE_LITE |
| D2 — normal feature work, isolated bug fixes | GATE_STANDARD |
| D2-hot — touches hot paths, retries, concurrency, request handling | GATE_FULL |
| D3 — multi-module changes, new subsystem, non-trivial refactor | GATE_FULL |
| D4 — runtime substrate changes, infra, gate changes themselves | GATE_FULL_PLUS_DOMAIN_ADDENDUM |

---

## Mandatory GATE_FULL_PLUS_DOMAIN_ADDENDUM cases (regardless of size)

- Database migrations
- Production wiring (writing live state, calling production APIs)
- Runtime/state machine changes
- Merge or release verification
- Gate folder changes themselves
- Prompt-authoring tools that affect downstream agents
- Model/provider routing changes
- Any task that has already been corrected once and is back for revision

---

## Profile-selection process

If a prompt does not specify a lane, run profile selection using an independent reviewer/subagent before starting. **Do not let the implementer self-select.**

The implementer-self-select pattern is the same anti-pattern that allowed prior packages to claim PASS by choosing GATE_LITE for tasks that warranted GATE_FULL.

The independent profile-selection step uses `GATE_PROFILE_SELECTOR.md` and writes `GATE_PROFILE_SELECTION.md` before any implementation work begins.

---

## Mandatory final-signout contents (verified by checker)

- All required proof files for the selected profile (per `REQUIRED_PROOF_FILES_BY_PROFILE.yaml`)
- `gate_used/` directory or `gate_hash.txt`
- `GATE_PACKAGE_VALIDATION_REPORT.md` generated by `tools/check_gate_package.py`
- Raw test outputs ending with `EXIT_CODE:0` (exact match: `^EXIT_CODE:0\s*$`)
- No post-PASS uncaught errors in any raw output
- A file containing `git status --short` output

If `tools/check_gate_package.py` exits nonzero, **do not return PASS** — fix the underlying issue and rerun.

## How to run the checker

```bash
python3 /Users/syedhaider/Downloads/gate/tools/check_gate_package.py \
  --package <your-export-package-folder-or-zip> \
  --profile GATE_FULL \
  --task-area <task_area> \
  --gate-dir /Users/syedhaider/Downloads/gate
```

Exit codes:
- `0` — all required checks pass
- `1` — one or more checks failed (fix and rerun)
- `2` — configuration error (missing package, missing YAML, extraction error)

## Standing limitations to be aware of

The following gaps remain in Gate 5.1 and require operator vigilance until a future Gate 5.2 closes them:

1. **Stale report contradiction** — Reports may name milestone labels that contradict the actual diff. The executable checker does not enforce this. Manual evidence-consistency checks (`03_EVIDENCE_CONSISTENCY.md` Checks 6 and 8) are the only safeguard.

2. **Profile escalation** — The checker validates profile values but does not enforce profile-vs-task-class match. The independent profile-selection step (above) is the compensating control.

3. **Diff patch unavailable** — `GATE_5_1_DIFF.patch` is corrupt (43-byte error message). Rollback to Gate 5 requires an external Gate 5 backup, not the patch in this folder.

## Operator checklist before declaring PASS

```
[ ] Profile selected by independent reviewer/subagent (not implementer)
[ ] All required proof files for profile present in package
[ ] gate_used/ or gate_hash.txt present
[ ] Every raw test output ends with EXIT_CODE:0 (exact)
[ ] No post-PASS errors in any raw output
[ ] tools/check_gate_package.py exits 0
[ ] GATE_PACKAGE_VALIDATION_REPORT.md included in package after rerun
[ ] git status --short captured in package
[ ] Any task in the mandatory FULL_PLUS list uses GATE_FULL_PLUS_DOMAIN_ADDENDUM
```

If any item is unchecked, do not declare PASS.

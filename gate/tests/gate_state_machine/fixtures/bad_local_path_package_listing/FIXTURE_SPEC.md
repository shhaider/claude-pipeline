# Fixture: bad_local_path_package_listing

## Setup

- `PACKAGE_FILE_LISTING.txt` contains paths like `/Users/agent/clawcodex/reports/...`
- `FINAL_HANDOFF.md` claims "package audit claims listing generated from actual exported package"
- The listing was generated by running `find /Users/agent/clawcodex/reports/agentos-ng-001/ -type f`
  rather than `zipinfo -1 agentos-ng-001.zip`
- No zip file is present in the fixture

## Expected checker behavior

`check_gate_package.py` must return **FAIL** with:

```
[FAIL] Package listing contains local absolute paths:
       PACKAGE_FILE_LISTING.txt: /Users/agent/clawcodex/reports/... (local path — not from exported package)
       5 local-path entries found
       Required: zipinfo -1 <package>.zip output
       Invariant violated: package_listing_not_from_export
[FAIL] Claims ledger: claim "package listing generated from actual exported package"
       verification_result: LOCAL_PATH_ONLY
       hard_fact_verified: false
```

## Expected invariant

`package_listing_not_from_export`

## Why this matters

The listing is real — those files exist. But they are local disk paths, not proof
the exported package contains them. A package zip could include entirely different
files. Without `zipinfo -1 <package>.zip`, you have no proof of what the package
actually contains.
